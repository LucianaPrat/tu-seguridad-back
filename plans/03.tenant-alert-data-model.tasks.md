## Confirmed inputs

- Merge the existing schema; no production data must be preserved.
- Every camera has monitor zones; every zone has an alert level.
- Snapshot images stay in MySQL for now.
- Wire/database codes are English; frontend translates labels.
- A matching DVR `external_id` keeps camera configuration; absent discovered cameras become
  unconfigured.
- A user belongs to one space; a space has many users through `space_members`.
- Face Auth identities are multiple/revocable per user.
- Camera and zone deletion is logical.
- Providers receive a unique correlation id for inbound acknowledgement.

## Deferred decisions

- Snapshot retention and external object storage.
- Live streaming.
- Detection cooldown/dedup.
- Notification provider, retry policy and inbound-webhook authentication.
- Polling versus DVR WebSocket/push transport.

## Migration inventory (T01)

| `User`, `UserRole`, seed admin | Replace | Extend user profile/lifecycle fields; move role to `space_members`; seed creates user, space, owner membership, DVR and routing defaults. Retain integer user ids for `hits`. |

| Stateless refresh JWT flow | Replace | `auth_tokens` hash, consume, revoke and rotate refresh credentials. Cookie transport remains HttpOnly. |
| Manual camera creation and scheduler lookup | Replace | Admin DVR initialization/discovery persists cameras; poll/push adapters read active configured cameras from this persisted source. |
| Existing camera/zone/event routes and OpenAPI | Replace | Breaking shapes ship under `/api/v2` unless a separately agreed v1 compatibility window is added before implementation. |
