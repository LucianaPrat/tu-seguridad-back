## Migration constraint review (T02)

- `space_members.user_id` is unique and `(space_id,user_id)` is unique.
- `dvrs.space_id` is unique; `cameras(dvr_id,external_id)` is unique.
- `monitor_zones_rectangle_bounds_check` rejects negative coordinates, non-positive dimensions and
  rectangles extending beyond 100 percent.
- `alert_events` foreign keys use `SET NULL` for camera, zone and snapshot historical references;
  ownership and membership relations use `RESTRICT`.
- `snapshots.data` is `MEDIUMBLOB`; no schema field stores a DVR-derived snapshot URL.
- `spaces.owner_user_id` is unique, so `User.ownedSpace` is a one-to-one relation, not a list.
- `cameras` carries one composite `(dvr_id, deleted_at)` index: every tenant-scoped read filters
  both columns together.
- `event_deliveries.error` is `TEXT`. At `VARCHAR(191)` a long provider error aborted the write
  that records the failure, leaving the row on its previous status.
- `dvrs.password_encrypted` is `VARCHAR(512)`, leaving room for a key-version prefix on the
  encryption envelope.

## Seed behavior (T02)

- The whole seed runs in one `prisma.$transaction`. A user without its space and owner membership
  is exactly the state the T04 login gate rejects, and the seed is documented as idempotent.
- `ADMIN_EMAIL` is lowercased before the upsert; email uniqueness is global and compared
  case-insensitively.
- Routing defaults enable `email` for both alert types and leave `call`/`whatsapp` disabled: email
  is the one channel that needs no provider account, and T06 still has to pick the others. Rows are
  inserted with `skipDuplicates`, so re-seeding never stomps a matrix the operator has toggled.
- `ADMIN_PASSWORD` is now required in production with a 16-character minimum
  (`src/cross/config/env-validation.schema.ts`). The seeded admin is active, profile-complete, owns
  the space and holds the `admin` membership, so a production seed run with the variable unset would
  have published that account under the placeholder committed in `.env.example`.

## Authentication decisions (T04)

- **Token claims.** The access token carries `spaceId`, membership `role` and `profileCompleted`
  next to `sub`/`email`, so no request derives its tenant from a resource id. A token missing
  `spaceId`/`role` is rejected by `JwtAuthGuard` rather than passed on: a pre-tenant token would
  otherwise reach an accessor with `undefined` as the space to scope by.
- **Deactivation lag is accepted and bounded.** `isActive` and membership are checked when a session
  is issued or refreshed, not on every request. Deactivating an account therefore takes effect at
  the next refresh — at most `JWT_EXPIRES_IN` (15 minutes). The alternative is a database read per
  request for a state that changes about once per employee.
- **Refresh tokens stay signed JWTs *and* become rows.** The standards require distinct secrets plus
  a `type` discriminator; the plan requires hash lookup, revocation and rotation. Both hold: the
  cookie value is a JWT, its hash is an `auth_tokens` row, and the row's `expires_at` is read back
  off the token's own `exp` so the two cannot drift.
- **Replay ends the family.** A refresh token whose signature verifies but has no usable row was
  already rotated, revoked or expired. That is either a stolen cookie or a client racing itself, and
  both are answered by revoking every refresh token the account holds. Rotation alone would let a
  thief keep racing the legitimate client.
- **Password reset is one transaction.** `AuthTokenAccessorService.consumePasswordReset` burns the
  token, writes the new hash and revokes every refresh token together. Split into three calls, a
  failure between them either loses the new password or leaves the sessions the reset was meant to
  end still valid.
- **Delivery is a port, not a provider.** `CredentialDeliveryPort` is what the domain depends on;
  `LoggedCredentialDeliveryService` is the placeholder until T06 picks a provider. Outside
  development it logs purpose and recipient only. In development it prints the raw token, because
  otherwise no local operator can accept an invitation or finish a reset, and the T07 smoke flow
  could not run at all. Production and test both take the redacted branch, so no shipped log and no
  fixture can carry a usable token — covered by a test.
- **Invited accounts start with placeholders.** Acceptance creates the user with empty name/phone and
  a hash of a discarded random secret, then hands out a `profileCompleted: false` session. Nothing
  can authenticate with that hash, and `ProfileCompletedGuard` blocks every route except `/auth/me`
  and `/auth/complete-profile` until the invitee sets its own values. This is the one place empty
  strings are reachable, and only while the flag is false — unlike the T01 `users` backfill, which
  would have produced the same shape on a *login-capable* account.
- **Password policy lives in one constant.** `AuthPolicy.MIN_PASSWORD_LENGTH` is 12, applied to
  registration, profile completion and password reset alike. A reset that accepted a weaker password
  than registration would be the way in. The frontend has to match this minimum.
- **Credential lifetimes are constants, not env vars** (`CredentialTtl`: magic link 15 min, password
  reset 30 min, invitation 7 days). They are product rules, not per-host tuning.
- **Account enumeration.** Magic-link and password-reset requests answer `{ accepted: true }` for
  every address, registered or not. `POST /auth/register` and `POST /invitations` deliberately do
  *not*: both return `CONFLICT` for an address that already has an account or a membership. That is
  a knowing trade — registration needs to tell the user why it failed, and inviting is an
  authenticated admin action inside one space — and it is the only enumeration surface left.
- **Authorization is declared, not remembered.** `@Roles(SpaceMemberRole.admin)` plus a global
  `RolesGuard`; `POST /invitations` is the first route to use it, and the DVR, member, routing and
  destructive-configuration routes from T05/T06 attach the same decorator. Both new guards throw
  rather than fall open when a request carries no user, so global guard registration order cannot
  turn either into a no-op.
- **One canonical sensitive-field list.** `src/cross/common/sensitive-fields.ts` is now read by both
  the Pino formatter and Sentry's scrubbers, matched case-insensitively, and covers `password`,
  `passwordHash`, `token`, `accessToken`, `refreshToken` and `faceToken` on top of the previous four
  names.
- **Routing defaults have one definition.** `ALERT_ROUTING_DEFAULTS` moved into
  `src/cross/common/constants.ts`; `prisma/seed.ts`, registration and the e2e fixture all read it, so
  a seeded space and a registered one cannot start with different matrices.

## Routes added (T04)

| Route | Access | Notes |
| --- | --- | --- |
| `POST /api/v1/auth/register` | public | Owner account, space, `admin` membership and routing defaults in one transaction. |
| `POST /api/v1/auth/login` | public | Generic rejection for wrong password, deactivated account and missing membership alike. |
| `POST /api/v1/auth/refresh` | public, cookie only | Rotates the stored token; rebuilds claims from the database. |
| `POST /api/v1/auth/logout` | public | Revokes the stored token as well as clearing the cookie. |
| `GET /api/v1/auth/me` | member, incomplete profile allowed | Profile plus `spaceId`, `spaceName`, `role`, `receiveAlerts`. |
| `POST /api/v1/auth/complete-profile` | member, incomplete profile allowed | Sets name, phone, password; issues a fresh pair carrying `profileCompleted: true`. |
| `POST /api/v1/auth/password-reset/request` | public | Always `202 { accepted: true }`. |
| `POST /api/v1/auth/password-reset/confirm` | public | One-time; revokes every refresh token. |
| `POST /api/v1/auth/magic-link/request` | public | Always `202 { accepted: true }`. |
| `POST /api/v1/auth/magic-link/consume` | public | Burns the link before issuing the session. |
| `POST /api/v1/auth/face/identities` | member | Re-enrollment revokes the previous active identity. |
| `POST /api/v1/auth/face/login` | public | Only active identities authenticate. |
| `POST /api/v1/invitations` | space admin | Returns id/email/expiry, never the token. |
| `POST /api/v1/invitations/accept` | public | Creates or links exactly one user and one membership. |
